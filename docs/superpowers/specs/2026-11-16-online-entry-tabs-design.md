# 멀티플레이 입장 화면 탭 분리와 칸별 오류 표시 설계

## 배경과 목적

멀티플레이 첫 화면은 `이름 → [방 만들기] → 방 코드 → [방 참가] → [기존 플레이어로 복구]`가 한 줄로 이어져 있다. 사용자 의견은 다음 세 가지다.

1. 이름 칸이 플레이어 이름이 아니라 방 이름을 정하는 칸처럼 보인다.
2. 방 만들기와 방 참가가 확실히 구분되면 좋겠다.
3. 이름 규칙 오류가 모든 버튼 아래에 떠서 눈에 잘 들어오지 않는다. 오류는 해당 칸 바로 아래에 떠야 한다. 비슷한 화면이 있는지 전수조사한다.

## 목표

- 첫 화면을 `방 만들기 | 방 참가` 탭으로 나눈다. 링크(`?code=`)로 들어오면 `방 참가` 탭을, 아니면 `방 만들기` 탭을 먼저 연다.
- 이름 칸의 라벨을 `내 이름`으로 바꾸고, 칸 아래에 플레이어 이름임과 규칙을 늘 보이는 도움말로 둔다.
- 특정 칸에 대한 오류는 그 칸 바로 아래에 띄운다. 칸과 무관한 오류(연결 실패, 방이 가득 참 등)는 지금처럼 일반 알림으로 둔다.
- 좌석 카드에서 이름을 고칠 때 생긴 오류(로컬은 토스트, 온라인은 화면 맨 위 알림)도 편집 중인 칸 바로 아래에 띄운다.

## 비목표

- 시작 칩·SB·BB 입력과 블라인드 예약의 오류 위치는 바꾸지 않는다(이미 칸 바로 아래, 버튼 위에 뜬다).
- 서버 API와 오류 코드는 바꾸지 않는다.
- 두 단계 화면(먼저 고르고 다음 화면으로 이동) 방식은 쓰지 않는다.

## 방식 비교 (사용자 선택: A)

- **A. 한 화면 탭 (선택)**: 페이지가 하나라서 단계가 늘지 않고, 링크로 들어온 사람에게 참가 탭을 바로 보여 줄 수 있다.
- B. 두 단계 화면: 구분은 가장 확실하지만 한 단계가 늘고 뒤로 가기 처리가 필요하다.
- C. 한 화면에 구역 상자로 나누기: 이름 칸을 두 구역이 함께 써야 해서 1번 문제가 남는다.

## 화면 구성

```
 멀티플레이 모드
 [ 방 만들기 ][ 방 참가 ]
 ───────────────────────
 (방 참가 탭)
 방 코드   [ AB12CD ]
           (방 코드 오류)
 내 이름   [        ]
           (이름 오류 또는 도움말)
 [ 방 참가 ]
 이전에 이 방에 참가했던 플레이어만 사용할 수 있습니다.
 [ 기존 플레이어로 복구 ]
 (칸과 무관한 오류)
 홈으로
```

- `방 만들기` 탭은 `내 이름`과 `방 만들기` 버튼만 보여 준다.
- 입력한 이름과 방 코드는 탭을 바꿔도 유지한다.
- 요청 중에는 탭 전환도 막는다.
- 복구 버튼 이름 `기존 플레이어로 복구`는 다른 안내 문구가 이 이름을 가리키므로 그대로 둔다.

## 오류를 칸에 묶는 규칙

| 원인 | 칸 |
|---|---|
| 입장 전 이름 검사 실패, `INVALID_NAME`, `DUPLICATE_NAME`, `RECOVERY_TARGET_NOT_FOUND` | 내 이름 |
| 복구 전 방 코드 형식 검사 실패, `ROOM_NOT_FOUND` | 방 코드 |
| 그 밖의 모든 오류 | 일반 알림 |

- 칸 오류는 `role="alert"`로 칸 바로 아래에 띄우고, 입력에 `aria-invalid`와 `aria-describedby`를 단다.
- 사용자가 그 칸을 고치거나 탭을 바꾸면 칸 오류를 지운다.
- 좌석 이름 편집은 입력 전에 화면에서 이름 규칙과 중복을 검사하고, 실패하면 편집 상태를 유지한 채 입력 아래에 이유를 띄운다.

## 화면 문구

- 합니다체를 쓰고 해요체를 쓰지 않는다. 호칭은 `플레이어`로 쓰고, `해 주세요`처럼 띄어 쓴다.
- 이름 도움말: `다른 플레이어에게 보이는 이름입니다. 한글·영문·숫자·공백 1~10자로 정해 주세요.`
- 복구 안내: `이전에 이 방에 참가했던 플레이어만 사용할 수 있습니다.`

## 구현자에게 맡기는 부분

- 탭과 오류 문구의 세부 스타일(색, 간격). 기존 `.field-error`의 색과 글자 크기를 따른다.
- 좌석 카드 안에서 오류 말풍선의 정확한 위치. 카드 크기를 바꾸지 않도록 입력 아래에 겹쳐 띄운다.
