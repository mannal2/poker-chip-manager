# Poker Chip Manager

실물 카드 게임의 칩·베팅 순서·팟·정산을 관리하는 단일 기기 토너먼트 앱입니다. 2~9명 노리밋, 수동 승자 선택을 지원합니다. 카드 배분·족보 평가는 사람이 진행합니다. 멀티플레이와 실제 서버 배포는 이 구현 범위에 포함하지 않습니다.

## 실행

Node.js 24 LTS와 npm을 사용합니다. 저장소 루트에서:

```powershell
npm --prefix frontend ci
npm --prefix frontend run dev -- --host 127.0.0.1
```

[단일 기기 화면](http://127.0.0.1:5173/local/)을 엽니다. `/`는 `/local/` 앱 홈으로 이동하고 `/online/`은 미제공 안내입니다. 앱 홈은 PWA 안에서 오프라인으로도 열립니다.

실제 오프라인/PWA 동작은 개발 서버가 아닌 프로덕션 빌드에서 확인합니다:

```powershell
npm --prefix frontend run build
npm --prefix frontend run preview -- --port 4173
```

[프로덕션 미리보기](http://127.0.0.1:4173/local/)에서 인터넷에 연결한 상태로 앱 파일을 처음 불러온 뒤 오프라인으로 사용할 수 있습니다. 파일 저장에 실패하면 홈에 안내가 표시됩니다. 브라우저의 홈 화면 설치 기능도 사용할 수 있습니다. 설치 가능 여부와 설치 UI는 브라우저에 따라 다릅니다. 실제 모바일 기기 검증 현황은 [DEVICE_CHECKS](frontend/DEVICE_CHECKS.md)를 참조하세요.

## 사용

- 앱 홈에는 단일 기기 모드, 멀티플레이 준비 중, 앱 업데이트가 있습니다. 단일 기기 모드는 저장된 게임을 자동 복원하고 없으면 P1/P2 두 명과 딜러 미선택으로 준비합니다.
- 중앙 −/+로 2~9명을 조절합니다. −는 좌석 순서와 무관하게 가장 최근 추가 참가자를 삭제합니다. P3 삭제 후 재추가하면 P3입니다.
- 준비 카드의 이름 글자를 누르면 그 자리에서 편집합니다. 글자 밖의 이름줄 빈 공간도 딜러 선택·드래그에 사용합니다. Enter/바깥 탭으로 저장, Esc로 취소하며 이름 입력 중에는 D/드래그를 막습니다. 입력 중 게임 시작은 초안을 버리지 않고 입력 완료를 안내합니다.
- 이름 이외 카드 영역을 누르면 즉시 첫 D 저장을 요청합니다(이전 500ms 대기 제거). 350ms 길게 누른 뒤 드래그하면 삽입 이동합니다. 첫 D를 선택해야 시작할 수 있습니다.
- 준비 화면 중앙 명수 아래 ↻는 카드를 시계 방향으로 한 자리씩 회전시킵니다. 실제 좌석 순서·딜러·턴은 바꾸지 않으며 드래그 자체는 화면을 회전시키지 않습니다.
- 시작 칩·SB·BB는 5 단위, 최대 1,000,000이며 `0 < SB < BB ≤ 시작 칩`입니다.
- 상단 HAND를 누르면 현재 토너먼트 기록, 경기 중 SB/BB를 누르면 다음 핸드 블라인드 예약을 엽니다. 예약은 `5 / 10 → 10 / 20`처럼 연한 색으로 표시하고 다음 핸드 적용 후 현재값만 남깁니다.
- 카드 왼쪽은 핸드 누적 납부액 + 미확정 추가액, 오른쪽은 저장된 잔액입니다. 칩 버튼과 올인은 초안만 채웁니다. BET으로 확정하고 C로 초안을 지웁니다. 콜/체크는 초안을 무시합니다.
- 단계가 바뀌면 단계 글자만 잠깐 금색으로 커졌다 돌아옵니다. 동작 줄이기 설정에서는 효과를 생략합니다.
- 베팅 완료 시 같은 화면에서 FLOP/TURN/RIVER로 자동 진행합니다. 별도 카드 공개·스트리트 시작 화면이 없으며 리버 완료/추가 베팅 불가 시 승자를 선택합니다. 실물 카드는 테이블의 단계를 확인해 직접 펼칩니다.
- 마지막 자발적 행동만 한 번 취소할 수 있습니다. 자동 단계 전환/정산 이후에는 그 이전 행동을 취소할 수 없습니다.
- 한 팟일 때는 POT만 표시합니다. 폴드 금액 차이만으로 사이드 팟을 만들지 않으며 실제 수령 자격이 다른 여러 팟만 따로 선택합니다.
- 정산은 자격 있는 카드를 선택합니다. 중앙 이전/다음으로 사이드 팟을 선택하고 팟을 눌러 지급 미리보기를 확인합니다. WIN은 전체 팟 정산과 다음 핸드 블라인드 납부를 한 번에 저장합니다. 최종 1명이면 종료합니다.
- 기록은 HAND·프리플랍/플랍/턴/리버/쇼다운·행동을 오래된 순으로 표시합니다. 우상단 버튼은 제목까지 전체 역순으로 바꾸므로 최신순에서 HAND는 해당 핸드의 맨 아래에 나옵니다. 베팅 행동·미콜 반환·실제 칩 수령을 핸드별로 묶고 취소한 행동과 내부 처리 기록은 숨깁니다.
- 기록·블라인드·관리 메뉴는 바깥 배경을 누르면 닫힙니다. 블라인드 입력은 가로 두 칸이며 예약하지 않고 닫으면 입력값을 적용하지 않습니다.
- 관리 메뉴는 앱 홈으로/새 토너먼트입니다. 별도 중단 버튼 없이 앱을 닫아도 저장 상태를 복원할 수 있습니다. 새 토너먼트는 확인 후 기존 게임과 기록을 삭제합니다.

## 저장·복구

상태와 전체 토너먼트 기록은 같은 브라우저의 IndexedDB에 저장합니다. **브라우저 저장소 삭제·시크릿 세션 종료·기기 변경 시 데이터가 소실될 수 있습니다.** 서버 백업이나 내보내기는 없습니다. 주소·포트·브라우저 프로필이 달라지면 별도 저장소입니다.

저장 실패 시 이전 확정 상태를 유지하며 다음 행동을 막습니다. `재시도`는 원래 요청을 사용해 이중 차감·지급을 방지합니다. 오류를 해결하기 위해 앱이 게임을 자동 삭제하지 않습니다. 지원하지 않는 저장 형식·규칙 또는 손상된 데이터는 원본을 보존하고 쓰기를 차단합니다.

같은 게임은 한 화면만 조작합니다. 일반 진입은 자동 복원하고 다른 창이 응답하면 조작을 막으며 `이 창에서 조작하기`로 명시적으로 인수할 수 있습니다. BroadcastChannel 응답 확인과 별개로 모든 저장은 조작 세대로 검증해 이전 창의 늦은 저장을 거절합니다. 홈 이동은 게임을 삭제하지 않으며 새 토너먼트는 확인 후 기존 게임과 기록을 교체합니다.

앱 홈의 앱 업데이트를 누르면 즉시 새 버전을 확인합니다. 최신/확인 실패/새 버전 준비 상태를 안내하고, 준비된 새 버전은 업데이트하기로 적용합니다. 별도 확인·닫기 버튼 없이 바깥 클릭이나 Escape로 닫으며 적용 중에는 닫을 수 없습니다. 저장 요청이 남으면 홈 이동·적용을 막고, 저장 완료 후에는 준비/진행 중인 게임이 있어도 적용할 수 있습니다. 적용 시 화면을 다시 열고 게임은 보존합니다. 대기 중 새 버전은 관련 창을 모두 닫은 뒤에도 활성화될 수 있습니다. 새 코드도 저장 형식·게임 규칙을 검증한 후 복원합니다.

## 검증

```powershell
npm --prefix frontend run typecheck
npm --prefix frontend run lint
npm --prefix frontend test -- --run
npm --prefix frontend run build
npm --prefix frontend exec -- playwright install chromium webkit
npm --prefix frontend run test:e2e
```

E2E는 로컬 4173 포트에서 테스트 빌드를 실행합니다. 해당 포트의 다른 서버는 먼저 종료하세요. 테스트 전용 표시/저장 fixture는 `--mode test`에서만 빌드되며 일반 제품 빌드에 포함되지 않습니다. PWA 테스트는 생성된 `dist` 파일을 일시 변경하고 원복하므로 검사를 동시에 실행하지 마세요.

순수 TypeScript 규칙 → IndexedDB repository/controller → React UI로 구성됩니다. [공통 JSON 사례](shared/game-fixtures/)는 수작업 기대값과 스키마를 사용합니다. [최종 디자인 계약](DESIGN_BASELINE.md), [구현 계획](IMPLEMENTATION_PLAN.md), [실제 검증·미검증 기록](IMPLEMENTATION_PROGRESS.md)을 함께 확인하세요.


태블릿에서는 화면 너비와 높이에 맞춰 UI가 함께 커지거나 작아집니다. 넓은 가로 화면은 높이에 맞는 너비만 사용합니다. 기본 화면에는 스크롤이 없고, 핸드 기록 창은 내부 스크롤과 더 보기를 유지합니다. 저장 정보를8초 내 불러오지 못하면 다시 시도 또는 기존 게임/기록을 교체하는 새 토너먼트 시작을 선택할 수 있습니다. 교체는 확인 후 저장 성공 시에만 적용됩니다.
